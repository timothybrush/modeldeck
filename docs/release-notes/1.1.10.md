# ModelDeck 1.1.10

This release is for the person with one Claude login and one Codex login who just wants to see their usage. ModelDeck now leaves your home folders alone in that case, and it fixes three things that went wrong for the first outside user who reported them.

**With one login per provider, ModelDeck never touches `~/.claude` or `~/.codex`.** Earlier versions pointed those folders at a ModelDeck-managed profile on the first add, which broke apps like T3 Code that resume conversations from the folder directly. Now the first login for each provider is read in place: no symlink, no shell hook, no profile folder. When you add a second login for the same provider, ModelDeck asks once whether it may manage switching for that provider, and only after you say yes does it start. Installs that already manage a folder keep working as before. A per-provider toggle in Settings is the override. (#648)

**Switching accounts no longer strands past conversations.** When you switch, every earlier conversation stays resumable by its session ID from the usual path, so a GUI client can pick up where it left off no matter which account is active. New conversations still land in the active account. Nothing is copied; each conversation has exactly one file. (#644)

**Re-adding a login asks instead of quietly making a numbered twin.** Removing an account leaves its folder on disk, and adding the same label again used to create `name-2`, `name-3`, and so on with the old history orphaned. Now ModelDeck shows what it found and offers Adopt existing or Start fresh. (#645)

**Codex profiles live under ModelDeck's own folder.** They were in `~/.codex-profiles`, so uninstalling left a live sign-in token behind. On first start the daemon moves them under Application Support with a verified backup and full rollback, and refuses while Codex is running. (#647)

**Also fixed**
- A native-installer `claude` in `~/.local/bin` now passes sign-in verify and renewal, not just login. Reported and fixed by Rick Dubiel. (#641, public #2)
- An account resting after its 5-hour limit no longer reads as "Proxy sign-in expired" with a useless Fix sign-in button. It says "Rate limited · back at 9:50 PM" in quiet gray. (#634)
- A day-old provider overload no longer wears a red "sign in again" banner. (#572)
- The login terminal no longer carries the proxy key, and the card names a stray login on its own. (#636)
- A failing Grok usage probe keeps its error attached to its caller instead of the daemon log. Contributed by Balogun Feranmi. (#639, public #5)

Under the hood: the Swift test suite no longer leaves a preferences file per fixture per run. (#616)
